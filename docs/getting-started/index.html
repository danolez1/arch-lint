Start here

Run your first checks.

arch-lint puts ESLint, Prettier, architecture rules, and headless CodeFlow analysis behind one install. Start with the checks your project already understands, then add architecture rules where they help.

Install

Use Node.js 20.9 or newer with npm, pnpm, or Bun. pnpm 11 projects may need the allowBuilds entries in the README. 

npm i -D @danolez/arch-lint
npx arch-lint init

The initializer adds project scripts and a starter config based on preset:recommended. Existing scripts are kept unless you pass --force.

Run the checks

npx arch-lint check

The command runs lint, format, and architecture checks in sequence. A failure in any stage returns a failing exit code for CI. If you want to run one part by itself, use arch-lint lint, arch-lint format, or arch-lint arch.

Choose the architecture rules

The starter preset keeps the first run small. Set a project-wide default, then enable the rules that fit your codebase. Layers let rules describe real boundaries such as services, contracts, and adapters. 

{
  "extends": ["preset:recommended"],
  "scan": ["src"],
  "defaultLevel": "off",
  "layers": {
    "services": ["src/services/**"],
    "contracts": ["src/contracts/**"],
    "adapters": ["src/adapters/**"]
  },
  "rules": {
    "interface-segregation": {
      "level": "error",
      "options": { "maxMethods": 5 }
    },
    "dependency-inversion": {
      "level": "error",
      "options": {
        "highLevelLayers": ["services"],
        "implementationLayers": ["adapters"]
      }
    }
  }
}

The example enables the interface-size check and flags service code that imports concrete classes from adapter files. See the configuration guide for layer patterns, exemptions, and baselines.
