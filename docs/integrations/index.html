Fits the project you have

Use the tools you already run.

Keep your project's lint and format configs, or use arch-lint's bundled defaults. The CLI can also run architecture analysis from ESLint, wire checks into Git, and expose graph information to MCP clients.

ESLint

The package exports an ESLint flat-config plugin with architecture and architecture-graph rules. The first runs configured architecture checks; the second limits the scan to graph analysis. 

import archlint from "@danolez/arch-lint/eslint-plugin";

export default [
  {
    plugins: { archlint },
    rules: { "archlint/architecture": "error" },
  },
];

The package also exports createConfig from @danolez/arch-lint/eslint for extending the bundled configuration.

Prettier

If the project has a Prettier config in its directory or a parent, arch-lint uses it. Otherwise the bundled config applies. Import the bundled preset directly when you need to extend it from your own config. 

// prettier.config.mjs
export { default } from "@danolez/arch-lint/prettier";

Biome

When a biome.json or biome.jsonc is present, the bundled ESLint and Prettier configs translate supported settings from it. Rules, formatter options, overrides, and ignore patterns are mapped where there is an equivalent. Unsupported settings are reported once to stderr.

Read the Biome mapping guide for its supported settings and limits.

Git hooks and CI

arch-lint hooks install writes pre-commit, pre-push, and commit-message hooks. arch-lint init --ci writes a GitHub Actions workflow. Add project-specific commands to the hooks section of the config when builds or audits should run with the built-in checks.

GitLab Code Quality report

The architecture command writes GitLab Code Quality JSON. It exits nonzero when it finds new violations, so upload the report with when: always to keep it available on failed pipelines. 

architecture:
  image: node:22
  script:
    - npm ci
    - npx arch-lint arch --format gitlab > gl-code-quality-report.json
  artifacts:
    when: always
    reports:
      codequality: gl-code-quality-report.json
npx arch-lint hooks install
npx arch-lint init --ci

The hook guide describes staged checks, pre-push migration checks, and hook configuration.

MCP

Run arch-lint mcp to start the Model Context Protocol server over standard input and output. The tools include check_violations, analyze_change, get_dependencies, get_architecture, analyze_file, and get_callgraph. The server also keeps its original archlint_* tool names for existing clients.

Findings include severity, the related principle, remediation guidance, whether a human should review it, whether the finding is a new regression, and a file and line location. Unused-export and orphan-type findings ask for human review. Filtered scans keep their totals scoped to the whole project.

CodeFlow

CodeFlow analysis runs separately from ESLint and Prettier. Use arch-lint codeflow analyze to write reports, blast radii, churn hotspots, duplicate-code groups, and candidate unused functions under .codeflow/. The unused-function scan is a heuristic, so treat those candidates as leads. The verify and audit commands check and record findings.

Language coverage

The dependency graph and structural architecture checks parse TypeScript and JavaScript variants. Python projects use ruff and mypy for lint and format, but do not get Python import-boundary graph checks. Dedicated Flutter rules inspect Dart. CodeFlow has a separate language set. --no-python skips the Python tools for a command.
