Architecture analysis

Find strain in the system.

The architecture engine checks source structure and project dependencies. Turn on the rules that match your boundaries, then use a baseline to introduce them without failing on existing findings.

Dependency graph

The graph resolves local imports across TypeScript and JavaScript files, including re-exports, aliases, and workspace packages. It can report file and package cycles, forbidden layer dependencies, cross-context imports, side-effect imports, and production imports of test files.

Cycles and boundaries Find circular dependencies and imports that cross configured layer or context boundaries.
Dependency reach Measure fan-in and fan-out, locate hub modules, and flag widely shared packages.

Architecture metrics

Graph output includes fan-in and fan-out for files. For configured layers it reports afferent coupling (Ca), efferent coupling (Ce), instability (I), abstractness (A), and distance from the expected balance (D). When layers have team ownership, the report also shows cross-team dependency ratios.

Rule What it reports Default limit
hub-module A file with high fan-in and high fan-out. 10 incoming and 10 outgoing files
high-coupling A file over either coupling limit. 20 incoming, 10 outgoing
hub-dependency An external package used by many source files. 10 importing files
vendor-coupling An external package used across architectural layers. One layer
max-instability A layer above its instability ceiling. 0.8
team-mismatch A layer whose dependencies cross team ownership too often. 50 percent

Design and structure

Structural project checks parse TypeScript and JavaScript. Depending on the rule, they inspect interfaces, declarations, imports, and references between symbols. They can flag overly large interfaces, concrete dependencies from high-level layers, unstable public APIs, disconnected module exports, unused exports, and types with no references. The opt-in dead-symbols rule reports unreferenced private functions, classes, and variables. The opt-in code-clone rule compares exact TypeScript and JavaScript statement tokens across source locations, including repeated runs within one block. Complexity, function size, nesting, and parameter checks help locate code that is getting difficult to change.

Some related signals come from the other tools in the package. ESLint reports unused local variables, while CodeFlow reports similarity groups and candidate unused functions. Those reports are separate from the architecture-rule registry and have their own command and output.

interface-segregation and dependency-inversion are opt-in rules. The first uses maxMethods (default 5). The second needs highLevelLayers and implementationLayers in its options.
